## Goal

Fix the three CI jobs that fail on every PR (`test`'s pip-audit step, `frontend`'s npm audit
step, `adapter-validate`'s schema-validate step) by bumping/pinning the flagged dependencies to
their fix versions and adding the missing `aiohttp` install. No product code changes — this is
dependency pins, lockfile, and CI-workflow only.

## Architecture

Three independent fixes, each scoped to a single failing step:

1. **Backend (`pip-audit`):** `python-jose[cryptography]==3.4.0` hard-pins `pyasn1<0.5.0`
   (verified via PyPI: `python-jose==3.5.0`'s `requires_dist` relaxes this to `pyasn1>=0.5.0`).
   Bump both, drop the now-obsolete `CVE-2026-30922` suppression from `ci.yml` and
   `.trivyignore`.
2. **Frontend (`npm audit`):** Verified live against the npm registry and OSV — **none** of the
   flagged packages require a major-version bump (react-router's fix line tops out at `7.18.2`;
   npm's `latest` dist-tag for `react-router-dom` is still `7.18.4`, so the spec's suppression
   fallback is not needed). `axios` and `react-router-dom` are direct deps (bump `package.json`);
   `brace-expansion`, `browserslist`, and — discovered live during planning, not in the original
   issue — `js-yaml`, `nanoid`, `postcss`, and `undici` (whose existing `overrides` pin sits
   exactly on the last vulnerable version) are transitive (pin/raise via the existing `overrides`
   block, following the `form-data`/`undici` precedent already in the file).
3. **CI (`adapter-validate`):** Verified live against `omniscient/dark-factory@main`:
   `factory_core/__init__.py` → `run_record` → `model_proxy` imports `aiohttp` at package-import
   time, and no other transitive package is needed. Add `aiohttp` to the job's `pip install` step.
   This fixes the job's first (schema-validate) step, which is all this issue diagnosed — but
   doing so exposes the job's second step (mirror-drift assert) for the first time, which fails
   for an unrelated, pre-existing reason (see point 4).
4. **CI (`adapter-validate`'s mirror-drift assert — out of scope, follow-up only):** Once point 3
   lands, the job reaches its "Assert mirrored values equal factory defaults" step for the first
   time and fails: `.factory/adapter.yaml`'s `safety` block has diverged from
   `omniscient/dark-factory`'s `adapter_defaults.DEFAULTS['safety']` since #808 added local
   security-hardening patterns. This is a cross-repo policy question, not tooling drift — file a
   follow-up issue and say so explicitly in the PR body; do not edit `.factory/adapter.yaml` in
   this PR.

Python (`pip-audit`, `python-jose`, `pyasn1`), Node/npm (`axios`, `react-router-dom`,
`brace-expansion`, `browserslist`), GitHub Actions (`.github/workflows/ci.yml`), Trivy

### Task 4 — Frontend: pin transitive deps (brace-expansion, browserslist, js-yaml, nanoid, postcss, undici)

**Files:** `frontend/package.json`, `frontend/package-lock.json`

#### TDD Steps

**Step 4.1 — Write failing test**

```bash
cd frontend
npm audit --audit-level=high --json \
  | python3 -c "import json,sys; d=json.load(sys.stdin)['vulnerabilities']; print(sorted(k for k in d if k in ('brace-expansion','browserslist','js-yaml','nanoid','postcss','undici')))"
```

Expected (before fix): `['brace-expansion', 'browserslist', 'js-yaml', 'nanoid', 'postcss', 'undici']`.
The last four are not in the spec (which flagged only `brace-expansion`/`browserslist` as
transitive) — verified live against OSV/npm during planning as additional high-severity
transitive drift on this branch, same class of fix (lockfile/`overrides`-only, no major
crossing). `undici` in particular is not new: the file already has an `overrides` entry for it
at `^7.28.0` (added for a prior advisory), but `7.28.0` is the *last* vulnerable version for
`GHSA-4cwx-7wf7-3272`/`GHSA-8xcm-r25x-g524`/`GHSA-jr45-8vmc-qm54`/`GHSA-m8rv-5g2x-5cg5`/
`GHSA-v3r7-h72x-cjcm` (range `7.0.0 - 7.28.0` inclusive) — so the existing pin must be raised,
not left alone.

`brace-expansion` needs care: it resolves to **two different versions in two different
lineages** in the current lockfile — confirmed via `package-lock.json`'s `packages` map:
- `node_modules/brace-expansion` → `5.0.6`, pulled by root `node_modules/minimatch` → `10.2.5`
  (a dependency of `@typescript-eslint/typescript-estree`), which declares `brace-expansion: ^5.0.5`.
- `node_modules/eslint/node_modules/brace-expansion`,
  `node_modules/@eslint/eslintrc/node_modules/brace-expansion`, and
  `node_modules/@eslint/config-array/node_modules/brace-expansion` → all `1.1.14`, pulled by
  each of those three packages' own bundled `minimatch@3.1.5`, which declares
  `brace-expansion: ^1.1.7`.

Both lineages are vulnerable (confirmed via OSV): `5.0.6` to all three GHSAs below; `1.1.14`
*also* to all three (their 0.x/1.x branches fix at `1.1.16`/`1.1.17`/`1.1.18` respectively — the
highest bar, `1.1.18`, is what clears all three on that line). A single top-level
`"brace-expansion": "^5.0.9"` override would force-upgrade the three `1.1.14` instances across a
1.x→5.x major boundary the spec forbids crossing, even though a same-major fix (`1.1.18`) exists
for them. Use npm's version-scoped override syntax to fix each lineage independently instead.

**Step 4.2 — Implement: extend the existing `overrides` block**

All six packages are transitive (no line in `dependencies`/`devDependencies`) — `brace-expansion`
via the two `minimatch` lineages above, `browserslist` via the Vite/PostCSS toolchain, `js-yaml`
via a build-tool dependency, `nanoid` via Vite, `postcss` via Vite/Tailwind, `undici` already
pinned once for an unrelated advisory — so pin/raise them all in the same `overrides` block
(`frontend/package.json:52-55`):

```json
// Before
  "overrides": {
    "form-data": "^4.0.6",
    "undici": "^7.28.0"
  }
```

```json
// After
  "overrides": {
    "form-data": "^4.0.6",
    "undici": "^7.29.1",
    "browserslist": "^4.29.0",
    "js-yaml": "^4.3.2",
    "nanoid": "^3.3.19",
    "postcss": "^8.5.28",
    "minimatch@^10": {
      "brace-expansion": "^5.0.9"
    },
    "minimatch@^3": {
      "brace-expansion": "^1.1.18"
    }
  }
```

Verified live (OSV + npm registry, 2026-09-16), all fixes staying on each package's
currently-resolved major (no major-version crossing anywhere):
- `brace-expansion` via `minimatch@^10` (`GHSA-3jxr-9vmj-r5cp`, `GHSA-mh99-v99m-4gvg`,
  `GHSA-rgw5-rvv9-x895` — fixed at `5.0.7`/`5.0.8`/`5.0.9` on the 3.x-5.x line): `^5.0.9` clears
  all three for the root instance.
- `brace-expansion` via `minimatch@^3` (same three GHSAs — fixed at `1.1.16`/`1.1.17`/`1.1.18` on
  the 0.x/1.x line): `^1.1.18` clears all three for the eslint-bundled instances, without
  crossing into a `5.x` major those `minimatch@3.x` consumers never asked for.
- `browserslist` (`GHSA-c83g-rgw3-j3cx`, `GHSA-73wf-gq98-2v4g` — fixed at `<=4.28.6`): `^4.29.0`
  clears both.
- `js-yaml` (`GHSA-2883-xcg3-v3hh`, `GHSA-52cp-r559-cp3m`, `GHSA-5p4m-2wfm-xmqj` — fixed at
  `4.3.2`/`4.3.0`/`4.3.1` on the 4.x line): `^4.3.2` clears all three; npm's `v4-legacy` dist-tag
  confirms `4.3.2` is the latest 4.x release.
- `nanoid` (`GHSA-28wg-ghj8-5hjv`, `GHSA-2v37-7h3g-55p8` — fixed at `3.3.16`/`3.3.18` on the 3.x
  line): `^3.3.19` clears both; npm's `legacy` dist-tag confirms `3.3.19` is the latest 3.x

- `postcss` (`GHSA-r28c-9q8g-f849` — fixed at `8.5.18`; also clears the newer,
